# 이호정 · 박소정 모바일 청첩장

청첩장 업체 계정에 의존하지 않고 직접 수정·빌드·운영하는 **Vite + React + TypeScript 정적 사이트**입니다. 서버·로그인·데이터베이스·방명록·참석 응답·방문자 추적은 없습니다.

아이보리 배경과 절제된 올리브색에, 글꼴은 **나눔손글씨 펜과 SUIT 두 종류**로 구성했습니다. 신랑·신부 이름과 다정한 멘트는 큰 손글씨로, 부모님 성함·‘의 아들/딸’·예식·교통·계좌·버튼은 읽기 쉬운 SUIT로 표시합니다. 화환 안내도 쉽게 찾을 수 있도록 크게 강조했습니다. 실제 웨딩사진과 2열 갤러리를 사용하며 사진은 원본 2:3 비율을 유지하고 전체가 보이도록 표시합니다. 데스크톱에서는 최대 480px 본문을 중앙에 표시합니다.

현재 설정은 **데모 모드**이며 실제 사진·계좌·사용자 제공 배경음악을 적용했고 연락처는 표시하지 않습니다. GitHub `main` 업로드와 `honbongmarry.co.kr` 도메인 구매는 완료했습니다. Cloudflare Worker `honbongwedding`의 Git 자동배포를 연결하고 있으며, 기존 Pages 설정을 Workers Static Assets 설정으로 교체했습니다. 배포 성공과 도메인·DNS·HTTPS 연결 완료 여부는 아직 검증하지 않았습니다. 카카오 JavaScript 키는 미설정입니다. 음악은 페이지를 열면 재생을 시도하며, 브라우저가 자동 재생을 막으면 첫 터치·클릭·키 입력에서 재시도합니다. 스크롤 중에도 유지하고 사용자가 일시정지한 선택을 존중합니다. 기존 임시 스톡은 청첩장 설정에서 사용하지 않고 파일과 출처 기록을 보존했습니다.

## 실행

현재 PC에는 시스템 PATH의 Node/npm이 없어서 프로젝트 전용 **Node.js 24.21.0 LTS**를 `.tools/`에 준비했습니다. 시스템 설정은 변경하지 않았습니다.

PowerShell에서 프로젝트 폴더를 열고 실행합니다.

또는 프로젝트 폴더의 `start-invitation.cmd`를 더블클릭하면 같은 개발 서버가 실행됩니다. 표시된 로컬 주소를 브라우저에서 열어주세요.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\portable.ps1 dev
```

미리보기: **http://127.0.0.1:5173/**. 종료는 실행한 터미널에서 `Ctrl+C`입니다. 실행 중인 같은 컴퓨터에서 접속합니다. 기본 서버는 인터넷이나 다른 기기에 노출되지 않는 로컬 주소에 바인딩합니다.

로컬 미리보기(`localhost`·`127.0.0.1`·IPv6 루프백)는 스크롤 효과를 기본으로 켭니다. 운영 주소는 기본적으로 시스템의 동작 줄이기 설정을 따릅니다. 화면 상단의 효과 전환 버튼은 제거했으며 Windows 설정은 변경하지 않습니다.

일반적인 다른 PC에서는 [Node.js 공식 LTS](https://nodejs.org/en/download)를 설치하고 다음 명령을 실행합니다.

```bash
npm ci
npm run dev
```

기존 개발 서버가 5173 포트를 사용 중이면 Vite가 표시하는 실제 주소를 확인하세요. `.tools/`는 개발용이며 배포 파일에 포함되지 않습니다. 의존성은 package-lock.json에 고정되어 있습니다.

## 빌드와 검사

```bash
npm run typecheck
npm run lint
npm test
npm run build
npm run preview
```

전용 Node를 사용한다면 `portable.ps1`의 마지막 인자를 `typecheck`, `lint`, `test`, `build`, `preview`로 바꾸면 됩니다. 프로덕션 미리보기 기본 주소는 http://127.0.0.1:4173/ 입니다.

- `npm run check:release`: 미완성 항목을 보여주되 실행·빌드는 허용합니다. 현재 데모 모드, A/B 음원 게시 권한, 개인정보·사진 공개 동의의 4개 경고가 남아 있습니다. 일반 `npm run build`도 이 경고를 출력하며 빌드를 차단하지 않습니다.
- `npm run check:publish`: 미완성 항목이 있으면 종료 코드 1로 **공개 배포를 막습니다**.
- `npm run deploy:check`: 만들어진 `dist/`를 Wrangler가 외부 업로드 없이 검사합니다. 먼저 `npm run build`를 실행합니다.
- `npm run deploy:workers`: 엄격 검사 → 빌드 → Cloudflare Workers 배포. 기존 공개 준비 검사를 유지하며, 현재 경고가 남아 있으면 배포를 중단합니다.

Cloudflare의 Git 자동배포는 빌드 `npm run build`, 배포 `npx wrangler deploy`를 사용합니다. 이 경로는 `check:publish`를 호출하지 않으므로 일반 빌드의 4개 경고를 배포 실패 원인으로 취급하지 않습니다. 상세 설정은 [Workers 배포 안내](docs/DEPLOYMENT.md)에 있습니다.

## 내용 수정

**[src/config/invitation.ts](src/config/invitation.ts)** 한 파일에서 관리합니다. 색상·폰트·여백은 [src/styles.css](src/styles.css)의 CSS 변수에서 바꿉니다.

| 변경 내용 | 설정 위치 |
| --- | --- |
| 이름·순서 | `couple` 및 필요한 `families[].person`, `share.title` |
| 날짜·시각 | `wedding.dateTime`, `wedding.confirmed` |
| 장소·교통·주차·ATM | `venue` |
| 초대·감사·화환 안내 문구 | `text`, 화환 안내는 `text.notice` |
| 부모님 성함·관계·표시 여부 | `families` |
| 전화·문자 | `contacts` |
| 계좌 그룹·은행·예금주·번호 | `accounts` |
| 사진 경로·순서·설명·표시 위치 | `photos` |
| 음악 파일·곡명·반복·권한 | `music` |
| BACKROOM 코드·음악·사진·영상 | `backroom` |
| 대표 도메인·OG 이미지·공유 | `share` |
| 정보 표시·공개 동의 | `privacy` |
| 공개 모드·감사 화면 | `mode`, `stage` |
| 유지 기간 기록 | `operation` |

날짜는 `YYYY-MM-DDTHH:mm:ss+09:00` 형식으로 입력합니다. 요일·해당 월 달력·D-day는 서울 날짜 기준으로 계산합니다. 미확정 상태에서는 예시 달력을 분명히 표시하고 ICS 저장을 막습니다. 확정된 일정만 `.ics`로 내려받습니다. 기본 예식 길이 60분은 달력 종료시간용 설정이며 예약 정보가 아닙니다.

부모님 성함은 `families[].members[].name`, 관계·자녀 성함·표시 여부는 `relation`, `person`, `visible`에서 조정합니다. `members[].memorial: true`인 성함 옆에 국화꽃을 표시합니다. `members`가 없는 이전 설정은 `names` 문자열을 사용합니다. 현재는 알려주신 가족관계를 사용하며 ‘장남·장녀’처럼 알 수 없는 순서를 넣지 않았습니다.

`text.notice`는 `stage: 'invitation'`인 초대 화면의 가족 소개 아래에 표시합니다. 현재 문구는 ‘화환은 정중히 사양합니다.’이며 초대 시와 별도로 관리합니다.

현재 연락처는 사용하지 않습니다. 이후 추가하려면 공개할 전화번호만 넣고 `consent: true`로 표시합니다. 번호가 없거나 공개 동의가 없으면 전화·문자 링크를 만들지 않습니다. 혼주 항목은 원하는 만큼 추가할 수 있습니다.

제공한 계좌 5개는 `accounts`의 신랑 측·신부 측 그룹에 입력했습니다. 공개 동의를 확인한 항목만 `sample: false`, `consent: true`로 설정합니다. 복사 값은 **`은행명 계좌번호`** 형식이며 예금주는 포함하지 않습니다. 연락처·계좌를 사용하지 않으면 `privacy.showContacts` / `showAccounts`를 false로 하고 실제 데이터를 배열에서도 제거하세요. 계좌 접기는 화면을 정리하는 기능이며 접근을 막는 기능이 아닙니다. 문서에는 계좌번호를 다시 기록하지 않습니다.

클립보드 사용이 실패하면 선택할 수 있는 수동 복사창을 표시합니다. 카카오 버튼은 SDK 미설정·로딩 실패·공유 호출 실패 시 **소개말·예식 설명·대표 URL**을 함께 복사해 대화창에 붙여넣도록 안내합니다. ‘링크 복사’는 URL만 복사합니다. 기본 공유는 지원 환경에서 `navigator.share`를 사용하고 미지원 시 URL 복사로 대체합니다.

카카오맵 버튼은 사용자가 제공한 [웨딩 시그니처 장소 링크](https://place.map.kakao.com/803348028)를 우선 사용합니다. `venue.kakaoUrl`이 없으면 기존 좌표·검색 링크로 대체합니다.

## 실제 사진과 음악 교체

사용자 폴더에서 선택한 실제 웨딩사진 10장을 반영했습니다. 대표 사진은 `YUP_0070.JPG`입니다. 원본은 `assets/user-originals/`에 그대로 보관하고 Git 제외 목록에 등록했습니다. **공개용 사본만** `public/images/`에서 제공합니다.

실제 사진 사본은 `wedding-{사진 ID}-{480,960,1440}.webp` 형식이며 WebP 품질은 84입니다. 원본 방향을 적용하고 EXIF/GPS/XMP를 제거했으며 색·밝기·사진 크롭은 변경하지 않았습니다. 공유 이미지는 `og-cover-actual.jpg`(1200×630px)입니다. 원본과 사본의 대응·크기·해시는 [사진 처리 기록](output/user-photo-preview/manifest.json)에 있습니다.

이후 다른 사진으로 바꿀 때는 원본을 별도 보관하고 웹용 사본을 만듭니다. Pillow가 있는 환경에서 한 장씩 변환하는 기본 도구는 다음과 같습니다. 아래 예시는 이번 10장 일괄 처리 기록과 별개입니다.

```bash
python scripts/optimize-images.py assets/user-originals/YUP_0070.JPG wedding-0070 --og og-cover-actual.jpg
python scripts/optimize-images.py assets/user-originals/YUP_1065.JPG wedding-1065
```

도구는 원본 방향을 적용하고 EXIF/GPS/XMP를 제거해 모든 사진에 가로 480·960·1440px, 품질 84의 WebP 사본을 만듭니다. `--og 파일명.jpg`를 지정하면 사진 전체를 아이보리 바탕에 담은 1200×630 OG 사본도 만듭니다. `photos`의 `src`, `srcSet`, `alt`, `position`을 수정하고 공유 대표 사진도 함께 교체하세요. 배열 순서가 갤러리 순서입니다. 실제 사진에는 `sample: false`, `share.imageSample: false`를 적용합니다. 현재 대표·갤러리 사진은 2:3 비율과 `object-fit: contain`으로 자르지 않고 표시하며 확대창에서도 전체 사진을 볼 수 있습니다.

사용자가 지정한 `music/A_song.mp3`를 변경 없이 `public/audio/A_song.mp3`에 복사했습니다. `music.src`는 `/audio/A_song.mp3`, `loop`는 `true`입니다. 음원 경로가 있으면 `preload="auto"`로 페이지를 열 때 재생을 시도합니다. 브라우저가 `NotAllowedError`로 자동 재생을 막으면 첫 터치·클릭·키 입력에서 재시도하며, 상단 버튼으로 재생·정지할 수 있습니다. 사용자가 일시정지하면 이후 동작으로 다시 켜지지 않습니다. 다른 재생 실패·파일 오류는 안내 메시지로 처리합니다. 파일 출처와 처리 기록은 [자산 출처](docs/ASSET_SOURCES.md)에 있습니다. `rightsConfirmed`는 웹 게시 권한의 별도 확인 항목이며, 로컬 재생과 구분해 공개 검사에서 확인합니다.

## BACKROOM 이스터 에그

청첩장 맨 아래 `BACKROOM ↗`를 누르고 **`honbong98`**을 입력합니다. 코드는 `src/config/invitation.ts`의 `backroom.code`에서 변경합니다. 입력창은 Enter로 제출하고 Escape로 닫습니다. 잘못된 코드는 안내만 표시하며 화면이나 음악을 바꾸지 않습니다.

입장하면 일반 청첩장을 숨기고 굵은 SUIT 글꼴을 사용하는 별도 다크 화면을 표시합니다. 일반 청첩장의 이름·멘트는 손글씨를 유지합니다. 입장 버튼의 사용자 동작에서 B 음악을 재생하며, A/B는 하나의 오디오 요소를 사용해 동시에 재생되지 않습니다. 돌아가면 원래 스크롤·포커스·A 음악의 재생 위치를 복구하며, 이전에 음악을 켜둔 경우에만 다시 재생합니다. BACKROOM의 `원래 청첩장으로` 또는 Escape로 복귀합니다.

백룸 표지에는 작은 `BACKROOM`과 큰 `작전명: 평생 한 팀` 제목을 표시합니다. 고정된 위치의 큰 이모지를 클릭하면 표정과 화면 전체의 초록·빨강·보라/청록 색감, 기분 문구가 바뀝니다. 이모지만 중심에서 회전하며 클릭 영역은 유지해 연속으로 누를 수 있습니다. 사용자 제공 사진은 포스터·대결 구도·필름·티켓 등의 배치로 표시하며 독사진은 `호냥이 VS 의정부 맑눈광`으로 묶었습니다. `backroom.photos`는 실제 비율과 접근 가능한 사진 설명을, `src/components/Backroom.tsx`는 장난스러운 화면 문구를, `src/backroom.css`는 스타일을 관리합니다.

포토부스 영상은 BACKROOM에서만 무음·인라인·자동 무한 반복을 시도하며 `preload="auto"`를 사용합니다. 재생 컨트롤이나 수동 재생 버튼은 표시하지 않고 영상에 직접 포인터·키보드 조작을 제공하지 않습니다. 자동 재생이 차단되면 이후 사용자 동작에서 재시도합니다. 영상의 설명 문장은 화면에서 제거하고 접근 가능한 이름은 유지합니다. 영상은 소리가 없는 H.264 파일이며, 종료할 때 재생도 정리합니다. 사진 10장의 원본은 `backroom image/`에 유지하고, 공개 WebP 사본에서 GPS/EXIF/XMP를 제거했습니다.

코드 입력은 클라이언트에서 처리하는 재미용 장치입니다. 서버 인증이나 비공개 저장소가 없고 코드·사진·음원·영상은 배포물에 포함됩니다. `backroom` 설정을 제거하면 입장 버튼도 사라집니다.

## 도메인과 호스팅

[Cloudflare Workers 배포·연결·운영 안내](docs/DEPLOYMENT.md)를 확인하세요. 구매한 대표 도메인은 `honbongmarry.co.kr`이며 GitHub `main`과 Worker `honbongwedding`을 사용합니다. 이전 [도메인 비교 자료](docs/DOMAIN_RESEARCH.md)는 참고 기록입니다. 도메인 갱신 비용은 정적 호스팅과 별개입니다.

`wrangler.jsonc`는 `assets.directory: './dist'`와 SPA 경로 처리를 사용하는 Workers 설정입니다. Node.js는 `.node-version`의 `24.21.0`을 사용합니다. Cloudflare의 Worker > Settings > Build에서 브랜치 `main`, 빌드 `npm run build`, 배포 `npx wrangler deploy`, 루트 디렉터리 빈 값으로 설정합니다. 공개 주소에는 Cloudflare Access 로그인 보호를 켜지 않습니다. 사용자 지정 도메인은 Worker > Settings > Domains & Routes > Add > Custom Domain에서 연결합니다. 외부 계정의 실제 배포·도메인 연결 상태는 대시보드와 HTTPS 접속으로 확인합니다.

최종 HTTPS 주소를 `share.siteUrl`에 입력하고 빌드하면 초기 HTML의 `og:url`, `og:image`, canonical도 같이 반영됩니다. 자바스크립트를 실행하지 않는 카카오 크롤러에도 제목·설명·대표 이미지가 전달됩니다. 도메인이 없는 데모의 OG는 임시 상대 이미지 경로이며 실서비스 공유 검수 대상이 아닙니다.

카카오 브라우저용 키와 두 종류의 도메인 등록, SDK/SRI, 캐시 갱신은 [연동 안내](docs/INTEGRATIONS.md)에 있습니다. JavaScript 키는 공개 가능한 브라우저 키이며 어드민 키·비공개 토큰은 이 설정에 넣지 않습니다.

## 개인정보와 예식 후 운영

`noindex` HTML 메타태그와 HTTP 헤더를 적용합니다. robots.txt는 검색봇이 noindex를 읽을 수 있게 접근을 허용합니다. **검색 제외 요청은 접근 제한이나 완전한 비공개를 뜻하지 않습니다.** 공개 사이트의 사진·계좌·연락처는 링크를 아는 사람이 접근할 수 있으며 프런트엔드 설정과 환경변수도 숨겨진 저장소가 아닙니다.

부모님 정보와 계좌·연락처의 공개 동의를 확인하고, 실제 개인정보가 들어간 저장소를 승인 없이 공개 저장소에 올리지 않습니다. 배포 토큰은 사용자의 로그인 세션 또는 비공개 배포 환경에서만 관리합니다.

예식 후 `stage: 'thank-you'`로 바꾸면 감사 문구와 사진·공유만 남고 일시·교통·가족·연락처·계좌를 화면에서 숨깁니다. 개인정보를 배포물에서도 없애려면 연락처·계좌 배열을 비우고 재빌드·재배포하며 이전 Workers 버전·미리보기 주소와 저장소 기록도 관리하세요. 표시 여부만 바꾸면 해당 값은 코드에 남을 수 있습니다. 종료 시 도메인의 자동 갱신과 이전 배포·저장소 기록도 직접 관리하세요. 공개 시작일은 미정이므로 1년 운영 종료일은 아직 확정하지 않았습니다.
