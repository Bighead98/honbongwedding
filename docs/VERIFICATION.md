확인 날짜: **2026-10-05, Asia/Seoul**. 사용자 제공 웨딩사진, BACKROOM 사진 10장·영상·B 음악, 신랑 측 2개·신부 측 3개 계좌를 반영해 검증했습니다. 기존 버전은 Cloudflare Workers에 배포되어 있으며, 이번 자동 재생·영상 조작 제거·백룸 폰트 변경도 로컬 빌드와 자동 테스트를 통과했습니다.

HTTP 결과 상세는 `artifacts/http-checks.json`, 음악·영상 구간 요청 결과는 `artifacts/media-http-checks.json`에 있습니다. 배포 크기는 **19,020,633 bytes(약 19.02 MB)**이며 글꼴·사진·음원·영상을 포함한 전체 파일 크기입니다. 원본 사진·전용 Node·node_modules는 배포물에 없습니다. 문장 글꼴은 나눔손글씨 펜과 SUIT 두 종류이며, 손글씨는 필요한 문자의 WOFF2 조각을 요청하고 SUIT는 400·600·800 굵기의 WOFF2 세 파일을 제공합니다.

현재 구현에서는 일반 청첩장의 손글씨를 유지하고 BACKROOM에는 굵은 SUIT를 사용합니다. A 음악은 음원 경로가 있으면 `preload="auto"`로 페이지를 열 때 재생을 시도하며, 자동 재생이 차단되면 첫 터치·클릭·키 입력에서 재시도하고 사용자의 명시적 일시정지를 유지합니다. B 음악은 코드 제출 동작에서 시작합니다. BACKROOM 영상은 무음·인라인·자동 반복을 시도하며, 컨트롤·수동 재생 버튼·영상 자체의 포인터·키보드 조작 없이 차단 후 사용자 동작에서 재시도합니다. 이번 변경의 상태 전환·재시도·정리는 아래 자동 테스트로 확인했으며, 실제 모바일 브라우저의 자동 재생 허용과 소리 출력은 별도 확인 대상입니다.

## 자동 테스트가 확인한 동작

- 서울 날짜 경계, 월말·연말·윤년, 올바른 토요일 오후 4:20 표시, 2026-10-04 기준 D-272.
- 미확정·잘못된 날짜의 일정 저장 거부. 확정 일정의 UTC 변환, ICS 줄바꿈·문자 이스케이프·한글 UTF-8 75바이트 접기.
- 공개 동의가 없거나 번호가 비었을 때 전화·문자 연결 방지. 숫자 없는 번호와 공백 계좌도 거부.
- 설정된 HTTPS 카카오 장소 URL을 우선 사용. 좌표 없이 확정 장소 검색 링크 제공, 비정상 좌표에서 검색으로 대체.
- 확대 갤러리를 main 밖 portal에 렌더링. 배경 inert·스크롤 잠금, 탭 포커스 순환, ESC 닫기, 열기 전 포커스 복구.
- 이전/다음 버튼·좌우키·가로 스와이프, 세로 동작에서는 사진을 바꾸지 않음.
- 사진 경로가 비거나 로딩 오류가 나면 설명 있는 대체 화면 제공.
- 계좌 아코디언, 복사 값이 `은행명 계좌번호` 형식이며 예금주를 제외, 주소 원문 복사.
- 신랑 측·신부 측 아코디언의 독립적인 열기·접기. 신부 측 세 계좌의 이름별 복사 값에 은행명과 합성 번호가 함께 포함되는지 검증.
- 클립보드 권한 거절/미지원 시 수동 복사창과 내용 선택. 키보드 좌우 선택을 방해하지 않음.
- A 음원 페이지 진입 시 재생 요청·반복·preload="auto". 캡처 단계에서 첫 동작을 처리해 전파가 중단된 입력과 초기 재생 응답 전 입력도 재시도. 페이지 복귀·화면 재표시·음원 준비에서 중단된 재생 복구, 준비 중 중복 요청 방지, 늦은 실패·StrictMode 초기 정리 후 상태 유지. 명시적 일시정지는 유지하고 화면 제거 시 리스너 정리. 파일 오류나 수동 재생 실패에서도 화면 유지.
- BACKROOM 미설정 시 입장 버튼 없음. 틀린 코드·입력창 취소에서 A 음악과 화면 유지, 초기 입력 포커스·Enter 제출·Escape 닫기·Tab 순환.
- 올바른 코드 제출 안에서 동일 오디오를 A 정지 → B 경로 적용 → load → play 순서로 전환. 일반 화면을 숨기고 백룸으로 이동. 복귀 시 A의 이전 재생 여부·위치·스크롤·포커스 복구. 자동 시작 대기와 사용자의 일시정지를 구분. 늦게 도착한 이전 재생 Promise·media 이벤트가 현재 상태를 덮어쓰지 않음.
- BACKROOM 사진 10장 각각 한 번 표시, 신랑·신부 독사진을 `호냥이 VS 의정부 맑눈광` 구도로 묶고 사진마다 별도 문구·배치 적용. 큰 이모지 클릭의 good → bad → hmm 순환·표정 변화·누적 회전값·연속 클릭 뒤 동일 버튼 및 포커스 유지·추가 구호 5개 검증. CSS 레이아웃과 실제 클릭 영역·회전 화면은 별도 실기기 확인 대상.
- BACKROOM 영상의 컨트롤·수동 재생 버튼 제거, 키보드 포커스 제외·컨텍스트 메뉴 차단. 무음·인라인·자동 반복과 차단 후 첫 동작 재시도. 기분·음악 상태 변경 시 영상 재시작 없음, 영상 클릭·키 입력 시 일시정지·되감기 없음, 무음 유지, 종료 후 재시도 정리.
- 카카오 SDK 미설정 시 SDK를 읽지 않고 소개말·예식 설명·대표 URL을 함께 복사. 별도 링크 복사와 기본 공유 미지원/실패에서는 URL만 복사, 취소에서는 강제 복사하지 않음.
- 모의 카카오 SDK가 준비되기 전 버튼 비활성, 초기화 후 클릭 안에서 동기 공유 호출, 정확한 절대 이미지 URL·링크 전달.
- 모의 SDK 로딩 실패/공유 호출 실패 시 소개말·예식 설명·대표 URL을 함께 복사하는 대안.
- 국화꽃은 이주은 성함 바로 옆에 한 개 표시하며 한자 표기가 없음. 이전 `names` 설정 방식도 지원.
- A/B 음악 파일이 모두 없으면 버튼과 오디오가 없음. B만 설정된 경우 입장 전 음원 경로를 읽지 않고 입장 동작 안에서 B를 재생. 연락처 링크·영역과 반복 안내 문구를 숨김.
- 효과 조작 버튼이 로컬·공개 주소 모두에 없음. ‘화환은 정중히 사양합니다.’를 초대 화면에 한 번 표시.
- 스크롤 시 문구를 한 줄씩, 갤러리 사진을 개별적으로 좌우 이동·확대하며 순차 표시. 화면 진입 후 한 번 실행하며 관찰 API 미지원·자동 모드의 동작 감소 설정에서 숨김이 남지 않음. 설정 변경·화면 제거 시 정리. 키보드 포커스가 들어오면 해당 항목을 즉시 표시.
- 사진·문구·장소·날짜·연락처·계좌가 비었을 때 안내 유지. 감사 화면에서 예식·가족·교통·계좌·연락처를 숨김.

전화번호·계좌·SDK·BACKROOM 전환 테스트는 **합성 데이터와 모의 브라우저 API**를 사용했습니다. 기본 음악 테스트는 실제 음원 설정을 읽되 재생 API를 모의 구현했습니다. 실존 계좌를 복사하거나 전화·문자를 발송하지 않았습니다. 실제 음악·영상 파일은 연결하고 디코딩·HTTP 전달까지 확인했으며 실제 브라우저에서 음악이 들리거나 영상이 자동 재생되는지 확인한 결과는 아닙니다.

스크롤 효과 훅은 `auto`·`on`·`off`를 지원합니다. 현재 화면은 로컬 미리보기에서 `on`으로 시스템의 동작 줄이기 설정과 관계없이 효과를 켜고, 운영 주소는 `auto`로 시스템 설정을 따릅니다. 사용자 요청으로 효과 조작 버튼을 제거했습니다. 초기 숨김은 화면 표시 전에 적용하고 두 프레임 뒤 관찰을 시작하며, 자동 모드에서 동작 줄이기를 켰다가 꺼도 구독을 통해 관찰을 복구합니다. 화면 정리 시 예약된 프레임과 관찰도 취소합니다.

Windows 설정은 읽기 전용으로 조회했으며 `SPI_GETCLIENTAREAANIMATION=false`, `MinAnimate=0`이었습니다. 이는 기존 효과를 중단시키는 시스템 설정 조건과 맞지만 실제 브라우저의 CSS 미디어 쿼리 값은 직접 확인하지 못했습니다. Windows 설정은 변경하지 않았습니다. 설정 관계는 [MDN의 prefers-reduced-motion 안내](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/%40media/prefers-reduced-motion), 조회 API는 [Microsoft SystemParametersInfo 문서](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-systemparametersinfoa)를 참고했습니다.

## 확인하지 못한 내용

Browser 런타임 연결을 시도하고 사용 가능한 브라우저 목록도 확인했으나 `No browser is available` 및 빈 목록이 반환되었습니다. 다른 브라우저를 임의로 연결하거나 인증·권한을 우회하지 않았습니다.

따라서 **렌더링된 실제 브라우저 화면, 가로 넘침, 실제 손가락 터치, 모바일/데스크톱 스크린샷**은 검증하지 못했습니다. JSDOM은 CSS 레이아웃과 이미지 디코딩·실제 음악 재생·OS 클립보드 권한을 구현한 브라우저가 아닙니다. 반응형 CSS를 작성하고 DOM·로직을 검증한 범위와 실제 화면 검증을 구분합니다.

아이폰, 안드로이드, 카카오톡 내부 브라우저, 실제 지도 목적지·앱 전환·공유 발송·일정 앱 가져오기, HTTPS·DNS·Cloudflare `_headers` 적용은 검증하지 않았습니다. `_headers`는 빌드에 포함되지만 Vite 로컬 서버에서 Cloudflare 응답 헤더가 적용되는 것은 아닙니다. 운영 OG 절대 URL과 카카오 미리보기는 최종 도메인이 아직 없어 검증하지 않았습니다.
